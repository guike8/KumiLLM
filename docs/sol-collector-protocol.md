# Kumi Sol Ultra teacher pilot

This queue connects the native Kumi `LanguageModel` interface to a Codex subagent configured as `gpt-6.1-sol` with `ultra` reasoning effort. It is a Codex agent file bridge, not a direct provider API sampling run. Only public answer text and tool calls cross back. Kumi executes every tool and supplies its actual results in the next request.

Apply `patches/kumi-sol-ultra-collection.patch` directly to upstream `2ff07a5be515e0a267ea86f7c3d56fa579b607ea`. It includes the v1 simulator/collection changes; apply this patch instead of the v1 patch, not on top of it. Existing v1 data, benchmark fixtures, and Studio LoRA training inputs are separate and unchanged.

## Launch

Use a **new** collection directory and an empty queue directory. The Studio command is:

```sh
KUMI_SOL_COLLECT_DIR=/absolute/new/sol-v2-pilot \
KUMI_SOL_QUEUE_DIR=/absolute/new/sol-v2-pilot-queue \
KUMI_SOL_EXECUTION_HOST=mac_studio \
KUMI_SOL_START=0 \
KUMI_SOL_LIMIT=4 \
KUMI_SOL_SERIES=S02 \
/absolute/path/eval_changes
```

The first four episodes are sequential and train-only by default. The collector allows at most 30 teacher calls across the pilot, waits at most 300 seconds per response, and sets each conversation turn's idle and hard limits to 600,000 ms. `KUMI_SOL_START` selects the first task index (0–3, default 0). `KUMI_SOL_LIMIT` is the number of consecutive tasks to collect (positive, default 4), bounded by the remaining tasks through index 3. `KUMI_SOL_SERIES` changes episode/project IDs and neutral fixture tags; it defaults to `S02` and must contain 1–32 ASCII letters or digits. Task-family grouping remains stable across series. No local GPU model is loaded by this collector.

For a new, targeted transport attempt, use **new** collection and queue directories with `KUMI_SOL_START=2 KUMI_SOL_LIMIT=1 KUMI_SOL_SERIES=S03`. It collects only `kumi-sol-v2-S03E03`; existing raw records and their original predicate outcomes remain untouched. The terminal manifest records `start_index`, `series`, and the actual collected episode count.

## Queue contract

The collector creates `requests/` and `responses/`. It atomically publishes `requests/<call_id>.json` containing exactly these top-level fields:

```json
{
  "episode_id": "kumi-sol-v2-S02E01",
  "call_id": "kumi-sol-v2-S02E01-c001",
  "request": {
    "prompt": [],
    "tools": [],
    "toolChoice": {"type": "auto"}
  },
  "model_requested": "gpt-6.1-sol",
  "reasoning_effort": "ultra",
  "teacher_transport": "codex_agent_file_queue"
}
```

`request` is the actual native model call, prepared with the same system instructions, word-only message conversion, active tools and automatic tool choice as the local-model binding. It includes the full conversation, actual tool outputs, and schemas supplied by Kumi. Provider metadata is removed. It contains no hidden verifier, expected-state object, or private teacher reasoning.

Read the request, choose the next public answer or calls, and atomically publish `responses/<call_id>.json`:

```json
{
  "call_id": "kumi-sol-v2-S02E01-c001",
  "tool_calls": [
    {"id": "teacher-001", "name": "an_offered_tool", "arguments": {}}
  ]
}
```

For a public final answer, use `{"call_id":"…","content":"…","tool_calls":[]}`. `content` is optional. Every tool call must use an offered tool name, a unique nonempty ID, and an arguments **object**. Unknown fields, string-encoded arguments, wrong call IDs, unoffered tools, empty responses, and private reasoning fields are rejected. Do not supply tool results, usage estimates, success labels, or private chain of thought. A malformed response fails that episode and remains in the queue for inspection.

Use a sibling temporary file and rename it when complete. Responses must be regular files at most 2 MB. Never pre-create a response before its request. Request and response IDs are generated by the collector, not taken from retrieved labels. The queue client may mirror these public files over the existing authenticated SSH connection; raw collection and tool execution stay on Studio.

The teacher should inspect only the actual queued requests and public task intent. It must not inspect the collector source, independent predicates, or raw verification files. On later calls it may read the updated conversation or newly appended exchanges, but the saved raw request always remains complete.

## Pilot tasks

These are newly authored tasks, separate from the published v1 templates and 18-case benchmark:

| Episode | Public intent |
| --- | --- |
| `kumi-sol-v2-S02E01` | Write an exact new MIDI melody into an empty Session slot and read it back. |
| `kumi-sol-v2-S02E02` | Make two different edits, then undo only the latest while retaining the first. |
| `kumi-sol-v2-S02E03` | Seek to bar 9 in 4/4 without playing, using a discovered transport tool and a fresh readback. |
| `kumi-sol-v2-S02E04` | Remember a producer preference, then apply it to a new track in a later turn. |

Names use neutral tags such as `S02E01`–`S02E04`, with the selected series prefix. The goals and predicates are authored independently of the teacher. Passing requires actual engine execution, fresh readback, exact unrelated-state invariants, and actual producer-file persistence where applicable. All episodes reject even temporary playback/recording. The preference must persist in the actual producer file before the second turn, with no first-turn DAW changes. Deferred transport evidence requires an actual `find_tools` call followed by an actual native `call_tool` for `set_transport` **or** a native `make_changes` call containing a `steps[].tool="set_transport"` step with object input. Both are supported Kumi execution routes; actual bridge position, stopped state, history and fresh-readback predicates still apply. Text mentioning tool calls is never execution evidence. These are synthetic Ableton simulator checks, with no real Live operation or audio-quality claim.

## Results and completion

Each attempted episode, including failures, is saved under `COLLECT_DIR/raw/<episode_id>.json` in the v1 raw-record envelope. It includes complete captured model requests and streamed public responses, before/after state, all actual bridge calls/results, independent checks, outcome, and honest teacher provenance. No token usage is fabricated. Failures remain raw material for quarantine; they are never silently promoted to training data.

`progress.jsonl` receives one line after each episode. A final atomically published `collection.json` manifest means the bounded collector finished and includes episode counts, predicates passed, provenance, and limitations. Its status is `raw_collection_complete_pending_strict_admission`; this does not mean training admission succeeded. The process exits 0 only when all episode predicates pass, and 1 when any fail. Independent normalization/admission must still quarantine failures and validate native calls/results before generating training examples.

Required provenance fields are `teacher="gpt-6.1-sol-ultra"`, `teacher_model="gpt-6.1-sol"`, `teacher_reasoning_effort="ultra"`, and `teacher_transport="codex_agent_file_queue"`. Scope is `executed_synthetic_kumi`. `KUMI_SOL_EXECUTION_HOST` labels the actual execution host; it is null unless explicitly supplied.

## Focused validation

From the patched Kumi checkout:

```sh
KUMI_NEXTEST=0 sh scripts/test-isolated.sh --offline --profile ci-release -p kumi --example eval_changes -- --nocapture
cargo build --locked --offline --profile ci-release -p kumi --example eval_changes
```

The new regressions cover strict public-response rejection, wrong/extra notes, atomic request publication and overwrite refusal, faithful stopped/playing and seek readbacks, transport undo, exact new MIDI-note readback without replacing existing clips, transient play/record rejection, first-turn persisted preference, negated preference rejection, actual deferred-call evidence, native transport composition, rejection of text spoofing/out-of-order/unrelated steps, and bounded targeted collection with safe new series IDs.

The corrected source passes all 14 native collector/simulator checks. Original pilot evidence used `patches/archive/kumi-sol-ultra-pilot1.patch`; its two rejected attempts remain unchanged. The current verifier accepts native `make_changes` transport composition and affirmative preference paraphrases while retaining actual state, persistence, no-play and preservation checks.
